# APK 배포 상태와 준비 항목

[English](binary-release.md) · [설치 안내](installation.ko.md) · [대응 소스 검사](source-correspondence.md)

## 서명된 실험용 APK

[v0.1.1-preview](https://github.com/hericobacter-spec/NaruVM/releases/tag/v0.1.1-preview)에서 ARM64 APK·두 소스 묶음·체크섬을 제공합니다.
[APK 안내](apk-release.ko.md)에서 검증 범위·설치·수정 방법을 확인하세요. 기존 v0.1은 소스 전용입니다.

## 이전 연구 APK에 대한 기록

아래는 새 서명 후보가 아닌 `55d78d6f…ee37` 연구 APK의 이전 판정입니다.
당시 보수적 검사 플래그와 생산 커밋 미입증 기록은 그대로 보존합니다. 현재 후보의 검증은 위 안내에 있습니다.

## 서명 미리보기 이전 배포 상태

**2026-11-17 확인:** [v0.1 릴리스](https://github.com/hericobacter-spec/NaruVM/releases/tag/v0.1)에는
프로젝트 소스 압축 파일과 체크섬이 있으며 **공개 APK는 없습니다.** 로컬 연구용 APK는
정식 배포 파일로 검증한 상태가 아닙니다. 지금 시험하려면 [소스 빌드·설치 안내](installation.ko.md)를 따르세요.
APK 제공은 준비할 목표이며, 소스만 제공하는 정책을 영구 유지하겠다는 뜻은 아닙니다.

## 확인한 내용

연구용 APK의 SHA-256은
`55d78d6f8077bce71dba7e6ad5add2d870b9b4632905b110bdddf5ecf345ee37`입니다.
2026-11-17 오프라인 검사에서 네이티브 파일 **53개 전부의 출처**를 대조했습니다.
27개는 고정된 외부 바이너리 패키지와, 26개는 로컬 빌드 결과와 일치합니다.
전체 대응 소스와 바이너리 배포 준비 상태는 여전히 `false`입니다.
[파일별 결과](../android/publication/source-correspondence.json)를 참고하세요.

프로젝트 소스·패치·라이선스·의존성 버전·빌드 도구는 공개했습니다. 별도로 모은 외부
소스 입력은 로컬에 있으며 현재 릴리스의 프로젝트 압축 파일에는 포함하지 않았습니다.
기여자는 [수집·검증 절차](publication.md#dependency-source-input-collection)로 준비할 수 있습니다.

## APK를 올리기 전에 마칠 일

아래 표는 프로젝트의 구체적인 배포 검사 항목입니다. APK 배포가 법적으로 가능하거나
불가능하다는 확정 의견이 아닙니다. 실험판이라는 이름만으로 소스·고지 의무가 없어지지는
않습니다. [라이선스 검토](licensing.md)와 실제 라이선스 본문을 함께 확인해야 합니다.

| 항목 | 현재 확인한 범위 | 남은 작업 |
| --- | --- | --- |
| 외부 라이브러리 | 바이너리·버전·후보 소스·레시피 기록 | 실제 포함 파일의 소스·패치·빌드 설정 확정 또는 보존된 입력으로 새로 빌드해 연결 기록 |
| NDK C++ 런타임 | 공식 바이너리 출처와 포장 과정 재현 | 기록된 소스·빌드 정보 공백 정리; 포장 재현을 소스 빌드로 표현하지 않기 |
| 소스 제공 | 프로젝트 압축 파일 공개, 외부 입력 수집 가능 | 실제 APK에 필요한 의존성 소스·빌드 자료를 함께 제공하고 링크·체크섬 기록 |
| 라이브러리 교체 | 소스와 빌드 도구 있음 | LGPL 구성 요소를 수정해 재결합하고 수신자 키로 서명·설치하는 절차를 별도 시험 환경에서 확인 |
| 배포 서명 | 로컬 연구용 서명 사용 | 별도 비공개 배포 키 선정, 인증서 지문만 공개, 업데이트·서명 차이 안내 |
| 실제 사용 확인 | 과거 태블릿 한 대의 제한된 관측 | 정확한 배포 후보의 첫 실행·고지·입력·정상 종료 확인, 전체 자동 설치와 다른 기기 미검증 명시 |

검사에 사용된 외부 패키지는 glib, libandroid-shmem, libandroid-support, libc++, libdrm,
libffi, libiconv, libllvm, libslirp, libwayland, libx11, libxau, libxcb, libxdmcp,
libxml2, libxshmfence, Mesa 소프트웨어 Vulkan, pcre2, zlib, zstd의 20개 버전입니다.
이 숫자는 **라이선스 위반 20건이라는 뜻이 아닙니다.** 실제 빌드 연결 정보가 미완료로
기록된 범위이며, 각 구성 요소와 결합 형태에 적용되는 의무를 판단해야 합니다.

해시 일치는 무결성·재현 검사에 유용하지만 소스 완전성을 대신하지 않습니다. 반대로
프로젝트의 보수적인 재빌드 검사를 모든 배포에서 바이트 단위 일치를 요구하는 법적 조건으로
설명해서도 안 됩니다. [GNU FAQ](https://www.gnu.org/licenses/gpl-faq.html#MustSourceBuildToMatchExactHashOfBinary),
[GPLv3 1·6절](https://spdx.org/licenses/GPL-3.0-only.html),
[LGPLv3 4절](https://spdx.org/licenses/LGPL-3.0-only.html)을 참고하세요.

## 향후 바이너리 릴리스 구성

준비가 끝나면 기존 v0.1 태그와 첨부 소스를 덮어쓰지 않고 별도 실험판을 게시합니다.

- 정확한 버전·커밋·빌드 구성이 연결된 `arm64-v8a` APK. 소프트웨어 렌더러·PanVK 포함 여부를 명시하고 Turnip 기본 포함으로 표현하지 않습니다.
- APK 체크섬, 서명 인증서 SHA-256 지문, 설치·업데이트 안내. 다른 키로 서명한 기존 연구용 앱은 그대로 업데이트되지 않으며 데이터 삭제를 기본 해결책으로 제시하지 않습니다.
- 적용되는 대응 소스·패치·설정·빌드/설치 도구·고지와 파일별 구성표.
- 실제 검사한 기기와 항목, 남은 충돌·느림, macOS 26·27과 전체 자동 설치 미검증 표시.

Apple 이미지·ROM·게스트 디스크·계정·서명 키는 APK나 소스 첨부에 포함하지 않습니다.

## 현재 검사 반복하기

실제 연구용 APK와 준비된 빌드·캐시가 있어야 합니다. 공개 소스만으로는 파일이 제공되지
않습니다. [검사 명령](source-correspondence.md#repeat-the-offline-checks)을 따르세요.
출처 대조는 통과해도 `--require-complete-source`를 붙이면 현재 미완료 상태에서 종료 코드
**2**가 반환됩니다. 소스 전용 CI 통과가 APK 배포 완료를 뜻하지 않습니다.
